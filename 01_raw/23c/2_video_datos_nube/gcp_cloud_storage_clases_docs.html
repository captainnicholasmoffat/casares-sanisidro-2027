Clases de almacenamiento Organízate con las colecciones Guarda y clasifica el contenido según tus preferencias.

En esta página se explica el concepto de clase de almacenamiento y las diferencias entre las clases de almacenamiento.

  • Para saber cómo cambiar la clase de almacenamiento de un objeto, consulta Cambiar clases de almacenamiento de objetos.

  • Para saber cómo cambiar la clase de almacenamiento predeterminada de un segmento, consulta Cambiar la clase de almacenamiento predeterminada.

Conceptos clave

  • Una clase de almacenamiento es un fragmento de metadatos que utilizan todos los objetos.

  • La clase de almacenamiento definida para un objeto afecta a su disponibilidad y a su modelo de precios.

  • Cuando creas un segmento, puedes especificar una clase de almacenamiento predeterminada para el segmento. Cuando añades objetos al segmento, heredan esta clase de almacenamiento, a menos que se indique otra explícitamente.

    • Si no especificas una clase de almacenamiento predeterminada al crear un segmento, se le asignará la clase de almacenamiento Estándar.

    • Cambiar la clase de almacenamiento predeterminada de un segmento no afecta a los objetos que ya estén en el segmento.

  • Puedes cambiar la clase de almacenamiento de un objeto de dos formas: reescribiendo el objeto o usando la gestión del ciclo de vida de los objetos.

  • Puedes habilitar la función Autoclass en un segmento para que Cloud Storage gestione las transiciones de clase de almacenamiento automáticamente.

En la siguiente tabla se resumen las clases de almacenamiento principales que ofrece Cloud Storage. Consulta las descripciones de las clases para obtener más información.

Almacenamiento estándar STANDARD Ninguno Ninguno
  • > 99,99% en regiones multirregionales y birregionales
  • 99,99% en las regiones
Nearline Storage NEARLINE 30 días Sí
  • 99,95% en multirregiones y regiones duales
  • 99,9% en las regiones
Almacenamiento Coldline COLDLINE 90 días Sí
  • 99,95% en multirregiones y regiones duales

1Consulta las descripciones de las clases para ver el SLA de disponibilidad de cada clase de almacenamiento.

Descripciones de las clases

Las siguientes funciones se aplican a todas las clases de almacenamiento:

  • Almacenamiento ilimitado con acceso ilimitado.
  • No hay un tamaño mínimo de objeto.
  • Accesibilidad y ubicaciones de almacenamiento en todo el mundo.
  • Baja latencia sin recuperación de datos offline.
  • Alta durabilidad (durabilidad anual del 99,999999999 %).
  • Redundancia entre regiones cuando los datos se almacenan en dos o más regiones.
  • Una experiencia uniforme con las funciones, la seguridad, las herramientas y las APIs de Cloud Storage.

Almacenamiento estándar

El almacenamiento estándar es la mejor opción para los datos a los que se accede con frecuencia ("datos en caliente") y para los datos que se almacenan durante periodos breves.

Cuando se usa en una región, el almacenamiento Estándar es adecuado para almacenar datos en la misma ubicación que los clústeres de Google Kubernetes Engine o las instancias de Compute Engine que usan los datos. Si colocas tus recursos en la misma ubicación, maximizarás el rendimiento de los cálculos que requieren muchos datos y podrás reducir los cargos de red.

Si se usa en una configuración birregional, seguirá disfrutando de un rendimiento optimizado al acceder aGoogle Cloud productos que se encuentren en una de las regiones asociadas, pero también obtendrá la mayor disponibilidad que supone almacenar datos en ubicaciones geográficamente separadas.

Cuando se usa en una multirregión, Standard Storage es adecuado para almacenar datos a los que se accede en todo el mundo, como contenido de sitios web, vídeos en streaming, cargas de trabajo interactivas o datos que admiten aplicaciones móviles y de juegos.

Disponibilidad

La disponibilidad de los datos de almacenamiento estándar es la siguiente:

Tipo de ubicación Acuerdo de nivel de servicio de disponibilidad1 Disponibilidad mensual habitual
multirregional 99,95 % >99,99%
dos regiones 99,95 % >99,99%
región 99,9 % 99,99 %

1El acuerdo de nivel de servicio de disponibilidad es el porcentaje de tiempo de actividad mensual respaldado por el acuerdo de nivel de servicio de Cloud Storage. Si Google no cumple ese tiempo de actividad, los clientes podrán recibir un crédito tal como se describe en el SLA de Cloud Storage.

Nearline Storage

Nearline Storage es un servicio de almacenamiento económico y duradero para almacenar datos a los que no se acceda con frecuencia. El almacenamiento Nearline es una mejor opción que el almacenamiento Estándar en situaciones en las que se aceptan una disponibilidad ligeramente inferior, un tiempo mínimo de almacenamiento de 30 días y los costes de acceso a los datos a cambio de unos costes de almacenamiento en reposo más bajos.

El almacenamiento Nearline es ideal para los datos que tienes previsto leer o modificar una vez al mes de media o menos. Por ejemplo, si quieres añadir archivos continuamente a Cloud Storage y tienes previsto acceder a ellos una vez al mes para analizarlos, Nearline Storage es una opción excelente.

El almacenamiento Nearline también es adecuado para copias de seguridad de datos, contenido multimedia al que no se accede frecuentemente y archivado de datos. Sin embargo, ten en cuenta que, si se accede a los datos con una frecuencia inferior a una vez al trimestre, Coldline Storage o Archive Storage son más rentables, ya que ofrecen costes de almacenamiento más bajos.

Disponibilidad

La disponibilidad de los datos de Nearline Storage es la siguiente:

Tipo de ubicación Acuerdo de nivel de servicio de disponibilidad1 Disponibilidad mensual habitual
multirregional 99,9 % 99,95 %
dos regiones 99,9 % 99,95 %
región 99% 99,9 %

1El acuerdo de nivel de servicio de disponibilidad es el porcentaje de tiempo de actividad mensual respaldado por el acuerdo de nivel de servicio de Cloud Storage. Si Google no cumple ese tiempo de actividad, los clientes podrán recibir un crédito tal como se describe en el SLA de Cloud Storage.

Almacenamiento Coldline

Coldline Storage es un servicio de almacenamiento muy económico y duradero para almacenar datos a los que no se acceda con frecuencia. Coldline Storage es una mejor opción que Standard Storage o Nearline Storage en situaciones en las que se aceptan una disponibilidad ligeramente inferior, un tiempo mínimo de almacenamiento de 90 días y costes más altos por el acceso a los datos a cambio de unos costes de almacenamiento en reposo más bajos.

El almacenamiento Coldline es ideal para los datos que tienes previsto leer o modificar como máximo una vez al trimestre. Sin embargo, si los datos se conservan únicamente con fines de copia de seguridad o archivado, Archive Storage es más rentable, ya que ofrece los costes de almacenamiento más bajos.

Disponibilidad

La disponibilidad de los datos de Coldline Storage es la siguiente:

Tipo de ubicación Acuerdo de nivel de servicio de disponibilidad1 Disponibilidad mensual habitual
multirregional 99,9 % 99,95 %
dos regiones 99,9 % 99,95 %
región 99% 99,9 %

1El acuerdo de nivel de servicio de disponibilidad es el porcentaje de tiempo de actividad mensual respaldado por el acuerdo de nivel de servicio de Cloud Storage. Si Google no cumple ese tiempo de actividad, los clientes podrán recibir un crédito tal como se describe en el SLA de Cloud Storage.

Almacenamiento de archivado

El almacenamiento de archivo es el servicio de almacenamiento más económico y duradero para el archivado de datos, las copias de seguridad online y la recuperación tras fallos. A diferencia de los servicios de almacenamiento "más fríos" que ofrecen otros proveedores de la nube, tus datos están disponibles en milisegundos, no en horas o días.

Al igual que Nearline Storage y Coldline Storage, Archive Storage tiene una disponibilidad ligeramente inferior a la de Standard Storage. Archive Storage también tiene costes más altos para el acceso a los datos y las operaciones, así como una duración mínima de almacenamiento de 365 días. Archive Storage es la mejor opción para los datos a los que tienes previsto acceder menos de una vez al año. Por ejemplo:

  • Almacenamiento de datos fríos: los datos archivados, como los que se almacenan por motivos legales o normativos, se pueden almacenar a bajo coste en Archive Storage y, aun así, estar disponibles si los necesitas.

  • Recuperación tras fallos: en caso de que se produzca un desastre, el tiempo de recuperación es fundamental. Cloud Storage proporciona acceso con baja latencia a los datos almacenados como almacenamiento Archive.

Disponibilidad

La disponibilidad de los datos de Archive Storage es la siguiente:

Tipo de ubicación Acuerdo de nivel de servicio de disponibilidad1 Disponibilidad mensual habitual
multirregional 99,9 % 99,95 %
dos regiones 99,9 % 99,95 %
región 99% 99,9 %

1El acuerdo de nivel de servicio de disponibilidad es el porcentaje de tiempo de actividad mensual respaldado por el acuerdo de nivel de servicio de Cloud Storage. Si Google no cumple ese tiempo de actividad, los clientes podrán recibir un crédito tal como se describe en el SLA de Cloud Storage.

Clases adicionales

Cloud Storage admite varias clases de almacenamiento antiguas adicionales. Sin embargo, estas clases no se pueden definir mediante la Google Cloud consola. Si no utilizas una de estas clases antiguas, te recomendamos que uses el almacenamiento estándar.

  • Multi-Regional Storage: es equivalente a Standard Storage, pero solo se puede usar para objetos almacenados en multirregiones o regiones duales.

  • Regional Storage: es equivalente a Standard Storage, pero solo se puede usar para objetos almacenados en regiones.

  • DRA Storage: es similar a Standard Storage, pero con las siguientes diferencias:

    • DRA tiene precios más altos para las operaciones.
    • DRA tiene un rendimiento inferior, sobre todo en lo que a disponibilidad se refiere (DRA tiene un acuerdo de nivel de servicio con una disponibilidad del 99 %).

    Puedes mover tus datos de DRA a otras clases de almacenamiento transfiriendo el almacenamiento.

Nota: Cuando habilitas la clasificación automática en tu segmento, las clases de almacenamiento antiguas se consideran diferentes del almacenamiento Estándar. Por ejemplo, los objetos de tu segmento que no estén eliminados de forma no definitiva se cambiarán a la clase de almacenamiento Estándar cuando Autoclass esté habilitado, incluidos los objetos almacenados en clases antiguas.

Precios

Las clases de almacenamiento afectan al modelo de precios de los objetos y a las operaciones que realices. Para obtener información sobre cómo afectan las clases de almacenamiento a los precios, consulta la página Precios de Cloud Storage.
